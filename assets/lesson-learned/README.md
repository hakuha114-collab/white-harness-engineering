# 踩坑经验

> 记录团队在开发过程中遇到的问题和解决方案，避免重复踩坑

## 落盘规范（强制）

- **每条记录一个文件**，命名：`YYYY-MM-DD-问题关键词.md`（如 `2026-08-03-redis缓存穿透.md`），存放在本目录。
- 本 README 的「经验索引」表同步追加一行，保持可检索。

## 记录模板

```markdown
# [问题简述]

- **发现时间**: YYYY-MM-DD
- **严重程度**: P0/P1/P2/P3
- **涉及模块**: [模块名]
- **问题现象**: [描述]
- **根因分析**: [5-Why]
- **解决方案**: [描述]
- **预防措施**: [如何避免类似问题]
- **关联 Rule**: [相关规则文件]
- **来源**: [fix-bug / code-review / deploy 复盘]
```

## 使用方式

1. Bug 修复后（fix-bug Step 7），按模板新建记录文件并登记索引
2. 代码审查发现共性问题（code-review Step 6），同上
3. 部署/运维问题复盘，同上
4. Agent 执行时，先检索本目录避免重复踩坑
