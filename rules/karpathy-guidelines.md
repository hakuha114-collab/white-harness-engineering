# Karpathy 编程原则红线（Rule 版）

> **唯一事实源（SSOT）**：执行细则、思考文档模板、操作流程以 `skills/karpathy-guidelines/SKILL.md` 为准。
> 本文件只保留审查/门禁使用的红线清单，不含执行细节；修改原则内容请只改 SSOT，本文件同步更新红线条目即可。
>
> 来源：[andrej-karpathy-skills](https://github.com/forrestchang/andrej-karpathy-skills)（MIT），基于 Andrej Karpathy 对 LLM 编程三大致命问题的观察。

## 🔴 四条红线（违反 = L1，审查直接标 [MUST] 打回）

### 原则一：先思考再编码

- [ ] 实现前**必须**明确陈述假设，不确定就问，不许猜
- [ ] 存在多种理解时，**必须**呈现多种解读，不许默默选一种
- [ ] 如果有更简单的方案，**必须**说出来，适时反驳
- [ ] 不清楚时**必须**停下来请求澄清

### 原则二：简洁优先

- [ ] **禁止**添加未被要求的功能
- [ ] **禁止**为单次使用的代码创建抽象
- [ ] **禁止**添加未被请求的"灵活性"或"可配置性"
- [ ] **禁止**为不可能发生的场景写错误处理
- [ ] 200 行能写成 50 行时**必须**重写

### 原则三：精准修改

- [ ] **禁止**"改进"相邻的代码、注释或格式
- [ ] **禁止**重构没有坏的东西
- [ ] **必须**匹配现有风格
- [ ] **必须**移除本次修改导致不再使用的 import/变量/函数；**禁止**删除之前就存在的死代码（除非被要求）

### 原则四：目标驱动执行

- [ ] 每个任务**必须**转化为可验证的目标（测试先行或成功标准明确）
- [ ] 多步骤任务**必须**声明「步骤 → 验证方式」计划

## 🟢 权衡说明

原则偏向谨慎而非速度。简单任务（错别字、一行修改）可自行判断，不必走完整流程。
