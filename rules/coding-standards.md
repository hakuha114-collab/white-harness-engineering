# 代码规范红线（SSOT）

> L1 级强制规则，违反即回退修复。本文件为代码规范**唯一事实源（SSOT）**；机器校验见 `scripts/check-code-style/`（违反即拦截），指令层不重复列清单。

## 1. 命名与可读性（判据式，不绑定特定语言风格）

- 命名清晰表达意图，避免无意义缩写；英文为主、避免拼音 / 中英混用
- 具体命名风格（camelCase / snake_case / PascalCase 等）遵循项目所用语言的官方 style guide（模型已内化，不在此复述）

## 2. 结构与尺寸（判据式）

- 函数 / 类 / 文件尺寸以**可读性与单一职责**为准；异常大尺寸须有说明
- 函数单一职责；嵌套层级以可维护性为准（过深须拆分）；无重复代码（DRY）
- 参数过多时使用对象传参；配置与代码分离，硬编码路径 / 地址须提取为配置

## 3. 注释

- 公共 API 须有文档注释；复杂逻辑须行内注释说明
- 禁止注释掉的代码（用 Git 管理历史）；代码应自解释，避免过度注释

## 4. 依赖管理（判据式）

- 依赖须有引入理由；版本须锁定（package-lock / requirements.txt）
- 禁止使用已知有 CVE 漏洞的依赖版本

## 5. 版本控制（true invariants 保留，其余判据）

- **禁止直接 push 到 main/master 分支**（不可逆，须走 PR）
- Commit 消息须清晰表达意图；分支按 `feature/xxx` / `bugfix/xxx` / `hotfix/xxx` 命名
