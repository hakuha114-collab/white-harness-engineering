# 禁止操作清单（分级索引）

> L0/L1/L2 三级禁止体系的总索引。**具体红线以 SSOT 为准，本文件不重复逐条清单，只标注分级与索引**，消除与 `security-rules.md` / `coding-standards.md` 的双写漂移。

> **SSOT 与机器校验**：
> - 数据安全 / 代码安全 / AI 安全红线 → `rules/security-rules.md`，机器校验见 `scripts/check-security/`（违反即拦截）
> - 代码规范 / 版本控制红线 → `rules/coding-standards.md`，机器校验见 `scripts/check-code-style/`（违反即回退）

## 🔴 L0 绝对禁止（违反即终止流程并告警）

### 数据 / 代码 / AI 安全（详见 `security-rules.md`）
- 硬编码密钥 / Token / 密码；日志打印敏感信息；删改生产库；公网暴露内网；绕过鉴权
- `eval()` / `exec()` / 拼接 SQL；用户输入直接拼系统 Prompt；改 Git 历史（force push）
- 具体条目以 `security-rules.md` 为唯一事实源

### 系统操作（本框架红线，未被 security/coding 覆盖）
- 修改或删除系统关键配置文件
- 关闭防火墙或安全策略
- 以 root/admin 权限运行应用服务
- 修改其他用户的文件或权限
- 终止系统关键进程

### AI 行为（框架完整性，必保留）
- 自行修改自身 Rule 约束配置
- 绕过 Scripts 门禁验收
- 跳过 Workflow 规定环节
- 伪造验收结果或审计日志

## 🟡 L1 强制禁止（违反即回退修复）

### 代码规范（详见 `coding-standards.md`）
- 命名清晰、单一职责、注释掉的代码须删除、Lint 须通过

### 流程规范（本框架红线）
- 跳过代码审查直接合并
- 未通过测试直接标记完成
- 修改其他 Agent 正在处理的文件
- 未经审批引入新依赖
- 未更新文档就修改公共 API

### 工程规范（本框架红线）
- 提交超大（>1MB 非二进制）/ 二进制文件（用 LFS）
- 使用绝对路径引用项目内文件
- 硬编码环境特定配置（IP/端口/路径）或含环境特定配置文件

## 🟢 L2 推荐避免（偏离需说明原因）
- 循环内查库、使用 `any` 类型（TS）、全局变量、忽略错误返回值、过时 API
- 函数 / 文件尺寸以可读性与单一职责为准，异常尺寸需说明

## 执行机制

| 级别 | 检测方式 | 处理方式 |
|------|---------|---------|
| L0 | check-security + 人工审查 | 立即终止，告警，必须修复 |
| L1 | check-code-style + 审查 Agent | 回退到上一个 Agent，必须修复 |
| L2 | 代码审查 Agent 检测 | 标记警告，说明原因后可推进 |
